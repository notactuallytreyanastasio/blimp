Actors Are Alive

March 22, 2026

One day. We built a REPL, an expression evaluator, an actor runtime with a registry, Elm-style error messages, compiled Blimp to native code via LLVM, and started on a TUI that'll make you forget you're in a terminal. Here's the whole thing.

The REPL

The REPL is a split-pane TUI. Left side is your session, right side is live state. Every variable you define, every actor you spawn, shows up on the right immediately. You always see the full picture.

blimp> x = 42
=> 42
blimp> y = [1, 2, 3]
=> [1, 2, 3]
blimp> y |> length(_)
=> 3
blimp> %{language: "blimp", version: 1, fun: true}
=> %{language: "blimp", version: 1, fun: true}

The state sidebar on the right updates after every evaluation. It shows x = 42, y = [1, 2, 3], name = "blimp". When you spawn actors, they show up there too as ref<Counter:1>. You're always looking at the full state of your session.

The evaluator handles everything: arithmetic with proper precedence, strings, atoms, booleans, lists, tuples, maps, pipes with _ placeholder, orelse for nil fallbacks, situation/case pattern matching, dot access on maps. Nine built-in functions: length, max, min, append, reverse, lookup, put, keys, now.

Actors: Templates, Spawn, Refs

This is the part that makes me grin. Actor definitions are templates. spawn creates instances. You get back a ref, and that ref is how you talk to it.

actor Counter do
  state count: Int :: 0

  on :increment do
    become count: count + 1
    reply count + 1
  end

  on :get do
    reply count
  end
end

c1 = spawn Counter     # => ref<Counter:1>
c2 = spawn Counter     # => ref<Counter:2>

c1 <- :increment      # => 1
c1 <- :increment      # => 2
c2 <- :increment      # => 1 (independent state)
c1 <- :get            # => 2
c2 <- :get            # => 1

Two instances of the same actor, completely independent state. c1 and c2 are lightweight refs, like Erlang PIDs. The actual state lives in a global registry. become updates state for the next message, not the current scope. That's real actor semantics, not a simulation.

Guards work too. on :withdraw(amount: Int) when amount > 0 only fires if the guard passes. Multiple handlers for the same message with different guards give you clean dispatch without nested conditionals.

Elm-Style Errors

I'm really proud of these. Every error tells you exactly what went wrong, shows you the code that caused it, and suggests what you probably meant.

blimp> bonk + 1

-- UNDEFINED VARIABLE ----------------------------

  bonk + 1
  I can't find a variable called `bonk`.

  Variables in scope:
      x = 42
      y = [1, 2, 3]
blimp> foobar(42)

-- UNKNOWN FUNCTION ------------------------------

  foobar(42)
  I don't know a function called `foobar`.

  Built-in functions:
      length, max, min, append, reverse,
      lookup, put, keys, now

Six error types, all with this format: UNDEFINED VARIABLE (lists what's in scope), TYPE MISMATCH, DIVISION BY ZERO, UNKNOWN FUNCTION (lists available builtins), NOT AVAILABLE IN REPL (suggests expressions to try), NO MATCHING HANDLER (names the actor and message). The Elm compiler set the bar for error messages and we're going for it.

Compiled to Native via LLVM

Separate from the REPL, we have a compiler. It takes Blimp source, runs it through the LLVM C API (called from Zig via @cImport), and produces a native binary.

$ echo "1 + 2 * 3" > hello.blimp
$ blimp-compile hello.blimp -o hello
$ ./hello
7

Right now it handles integer and float arithmetic, comparisons, and unary ops. The codegen creates an LLVM module, adds a main function, compiles the expression tree into LLVM IR instructions, emits an object file, and shells out to cc to link against a tiny C runtime that provides blimp_print_int. It's a prototype, but it's a real compiler producing real machine code. The REPL interprets, the compiler compiles, both from the same parser and AST.

The Multiplexer

The diff viewer grew a sibling. The agents page at /agents is a multiplexer that runs up to four Claude sessions in a split-pane grid. Each pane streams output in real time. You can click lines in the diff viewer, write commentary about what you want changed, and it spawns an agent that jumps into the multiplexer view.

Everything is URL-parameterized: /agents?panes=12,34&dark=1 restores exactly which panes are open and whether dark mode is on. Navigate away and come back, you're right where you left off. Permission requests from the agent show up as Allow/Deny buttons inline in the output. It feels like a real IDE, not a chat window.

Agent Decision Trees

Here's the weird one. Every agent that spawns from the multiplexer gets a root node in the deciduous decision graph. The agent's system prompt tells it to log its reasoning: goals, options, decisions, actions, outcomes. All linked to its root node.

When the agent dies, its decision subtree stays in the graph. A new agent can pick up where the dead one left off. Active agents can see what other agents are working on, which files they're touching, what they've decided. The deciduous trees merge when agents agree and surface conflicts when they disagree.

This is the "each agent would have a deciduous tree" idea from the original charter. It's real now.

The Design Stack

We also wrote four design documents today:

  • compilation.md: The full pipeline from AST to LLVM IR. Blimp IR design, runtime type representation, actor struct layout, Perceus RC, five build phases.
  • repl.md: REPL architecture, the evaluator, state sidebar, Elm errors, multi-line input, actor runtime, LiveView integration.

What's Next

The TUI is getting rebuilt with libvaxis, a proper terminal UI framework. TEA architecture, vim navigation (normal/insert/command modes), syntax highlighting, tab completion, scrollable panels, mouse support. The current raw ANSI version works but it's janky. The next version will feel like a real editor.

After that: the Blimp IR (lowering AST to SSA basic blocks), then codegen for data structures, then the actor runtime in compiled code. Per-actor arenas, Perceus reference counting, and a preemptive scheduler with reduction counting. The BEAM solved this 30 years ago. We're solving it in Zig targeting WASM. Same semantics, different century.

This is as much art project and craft experiment as it is any real attempt at making a useful tool. But the actors are alive, and that feels pretty good.
